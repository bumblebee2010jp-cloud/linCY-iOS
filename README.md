## 0.2.16：原生相册备份界面与预览

以 0.2.15 源码为基础，只调整 App 自带的“相册备份”页。原版功能中的网页和“选文件/文件夹跳浏览器”保持原样。

- “检查同名大小”移到“开始备份”右边，两个操作各有独立 `ⓘ` 圆形按钮，点击才显示说明。检查进度、停止和结果清单继续保留；检查和备份互斥，避免并行操作。
- 相册勾选保留：点左侧圆圈勾选，点名称/封面进入预览，两种点击分开。开始备份与检查仍处理全部勾选的本机相册，“同步选中”仍处理全部勾选的服务器相册，不改为只操作当前预览相册。
- 服务器相册长按可隐藏/取消隐藏；隐藏后取消勾选，移至底部“已隐藏相册”。隐藏记录按服务器地址保存在手机，不删除服务器文件；全选、同步选中、同步全部都排除已隐藏服务器相册。确认同步时会再次过滤隐藏项。
- 本机相册与服务器相册都能点击进入照片/视频浏览页；照片浏览页没有勾选圈，点击即可全屏大图预览，支持前后切换。本机照片可双击/捏合缩放；服务器图片使用 WebKit 页面缩放。视频提供播放控件，退出预览停止当前视频。
- 相册页和照片浏览页均有“排列”菜单：列表、小图标（4 列）、中等图标（3 列）、大图标（2 列）。相册和照片分别记住排列设置。
- 本机使用 PhotoKit 加载缩略图与视频，按需分页显示，不导出全相册来预览；iCloud 内容可能需要下载。服务器沿用网页相册的认证、分页、缩略图、图片预览及原视频接口；大视频流式播放，不先整段下载。
- 预览是只读浏览，没有添加删除、保存或逐张勾选操作；备份、同步、同名不同大小检查仍由原有任务逻辑执行。

新增 `linCY/AlbumBrowser.swift` 已加入 Xcode Sources。工程版本为 **0.2.16 (16)**；用 `linCY.xcodeproj` 编译。

## 0.2.12 修正：误报「服务端未确认保存原相册时间」

- 服务端（original-time 版）把拍摄时间写进相册目录下的 `.lincy-photo-dates/<文件名>`，
  内容是 `{"version":1,"date_ms":…,"size":…,"modified":…}`，同时把文件 mtime 设为拍摄时间，
  但**上传响应里不一定回 `creation_date_ms` 字段**。原逻辑把「响应缺字段」当成失败，
  于是出现「文件已被接收，但服务端未确认保存原相册时间」——文件其实已经正确落盘。
- 现在：响应里的确认字段存在且与发送值不一致才判失败；字段缺失不判失败，只在日志提示一次。
- 确认字段兼容数字与字符串两种写法。
- 0.2.11 的只读「检查同名不同大小」保留：勾选相册 → 点按钮 → 逐张导出比对 → 列表 + 可复制清单。

## 0.2.13 修正：检查同名不同大小永远报 0

- 根因：相册目录不在「备份根」下。备份根是 `mobile.json` 的 `upload_dir`（如 `E:\iPhone15Pro\Backup`），
  相册实际在 `album_dir`（如 `E:\iPhone15Pro\Video\Photos`）。
  之前用 `/api/upload-contents?path=<相册名>` 查的是备份根，返回空清单，
  所有文件都没进入比对，结果永远是 0。
- 改用与反向同步同一条路径：`/api/album/photos?album=&offset=` 分页拿相册文件列表，
  并用 `GET /api/albums` 的目录名做匹配（先按安全目录名，再按相册标题，大小写不敏感）。
- 服务器端大小改为 `HEAD /api/album/photo?album=&name=` 读 `Content-Length`，
  不再为了比大小把整张照片重新下载一遍。
- 新增诊断日志：每个相册一行「服务器 N 个文件（目录 X）」，
  结束时一行「检查汇总：同名 A 个，读到服务器大小 B 个，不一致 C 个」。
